`--num_bands 3 --point_kernel 3` = 커널 사다리 {3, 5, pool}. (MID=5 는 코드 기본값)

> ⚠ **명령 형태를 바꾸지 말 것.** `--band_kernels 3,5` 는 **같은 아키텍처지만 초기화가
> 다르다** — `band_kernels` 경로가 `conv_point` 를 재생성해 난수 스트림이 밀린다.
> 같은 시드인데 Steel 실패율이 5% vs 15% 로 갈렸다. 비교/재현은 위 형태로 통일한다.

## 1. 순전파

```
입력 (96 × D)
  ├─ RevIN 정규화                means detach / stdev gradient 통과 (half-RevIN, 의도적)
  ├─ [in_proj 제거]              선형 채널믹서 D→D 를 뺌
  ├─ 3 branch — 다중 스케일
  │     depthwise conv k=3       수용영역 3
  │     depthwise conv k=5       수용영역 5
  │     AvgPool(4) → 보간 복원    실효폭 ~8
  ├─ [DTK 제거]                  공유 시간커널(D→16→conv→D) 를 뺌
  ├─ 밴드별 FFT 게이트            각 밴드의 스펙트럼 에너지 → softmax → 가중치 3개(샘플마다)
  ├─ 가중합                      hidden = Σ gᵢ · 밴드ᵢ
  ├─ 잔차 MLP                    hidden += W_up(GELU(W_down(hidden)))  D→16→D
  │                              ← 채널믹싱 + 유일한 비선형 (ci_full 에서는 1→16→1 = 비선형만)
  ├─ SPK 헤드                    주기 접기 → 위상별 공유 선형 → (H × D)
  │                              ← 출력 시점이 서로 독립 = 스트리밍 가능한 이유
  └─ RevIN 역정규화 → 예측
```

**452 파라미터** (Steel D=6, H=96). 직전 shipping 822p 대비 **−45%**.

## 3. 왜 {3,5}(3밴드)인가 — val 1위를 안 골랐다

커널 사다리 격자 6개(b2_3 / b2_5 / b3_35 / b3_37 / b4_357 / b4_359)를 mfg-6 에서 val 로 비교:

- **격자 전체가 0.28% 안에 몰림** = val 신호가 노이즈 수준, 변별력 없음.
- val-rank 1위는 `b4_357`(508p)이나 Steel 실패율 **35%**.
- 채택한 `b3_35`(452p)는 실패율 **15%**.

→ **격자에 변별력이 없을 때는 안정성과 파라미터로 동점을 깬다.** 논문에 이 근거를 명시.

## 6. 하이퍼파라미터 정책 — 베이스라인과 대칭

- `_DATASET_OVERRIDES` 확인 결과 **베이스라인은 mfg 에서 아무것도 튜닝하지 않는다**
  (논문 default 그대로, 주기 모델만 period). 우리만 08-14 에 27-config 그리드를
  mfg 에 돌려 canonical 을 골랐었다 = **우리만 유리한 비대칭**.
- → **LTSF 에서 정한 단일 설정을 mfg 에 그대로 쓴다. mfg 서치 없음.**
- LTSF per-dataset 튜닝도 **해봤더니 손해**: val 기반 per-dataset 선택 0.2504 vs
  단일 설정 0.2501. 격자가 0.7% 안에 몰려 val 이 노이즈. → **12데이터 전부 단일 설정.**
  베이스라인은 per-dataset 튜닝을 유지하므로 **우리에게 불리한 조건** = 공정성 방어 문장.

## 9. 남은 작업

1. **mfg shipping** 4호라이즌 × 3시드 — 실행 중 (`results/probes/feather_mfg_new.csv`)
