# 사전 등록: FEATHer-mix 재설계 — 베이스라인과 같은 규칙으로 고르기 (2026-10-12, 실행 전에 작성·커밋)

## 왜
베이스라인은 저자 설정 후보 여러 개 중 검증 손실 1등을 쓰는데(`docs/chosen_mfg.json`), FEATHer-mix 는 설정 하나로
고정돼 있다. 같은 규칙을 FEATHer 에도 적용한다. 공정한 재실험 뒤 DiPE(모든 칸 칩 안)가 MSE 22/24 칸에서 앞서고,
검증 손실로 보면 그 차이는 RevIN 을 끈 설정에서 나온다(같은 DiPE 의 RevIN 켠 후보는 MetroPT3·WindSCADA 에서 FEATHer 보다
4~12 % 나쁘고, 끈 후보는 12~13 % 좋다). 그래서 후보는 정규화(값의 수준 정보를 얼마나 남기는가)와 학습률이다.

**정직 공개**: FEATHer 의 테스트 결과는 이미 여러 번 봤다(9월 개발 포함). 그래서 이 재설계는 **검증 손실만**으로 고르고,
테스트는 고른 하나에 대해서만 한 번 본다. 시도한 후보 수(아래 전부)와 이 문서를 논문에 공개한다.
알려진 위험: 9월 "섞기 입력에 원시 수준 넣기"와 10-01 RevIN 끄기 ablation 은 검증에서 비슷하거나 좋았지만 테스트에서
EWELD·N2O·BlastFurnace 가 크게 나빠졌다(검증→테스트 사이 수준 변화). 규칙대로 고른 결과가 테스트에서 나빠도 그대로 보고한다.

## 후보 (`tools/results/protocol.py` `REDESIGN_ARMS`, 모두 FEATHer-mix 동결 설정 + 아래 한 가지)
| id | 내용 | 코드 |
|---|---|---|
| A `frozen` | 지금 모델 (RevIN: 창 평균·표준편차) | — |
| B `rd:mean` | 평균만 빼기, 창 표준편차로 나누지 않음 | `--revin_mode mean` |
| C `rd:norevin` | 정규화 없음 | `--no_revin` |
| D `rd:learnlevel` | x_norm = (x − a·평균)/표준편차, a 는 채널별 학습값(1에서 시작 = A) | `--revin_mode learn_level` |
| E `rd:mixstats` | RevIN 유지 + 잔차 섞기 MLP 의 병목이 각 채널의 창 평균·log 표준편차도 읽음(0 초기화 = A) | `--mix_stats 1` |

새 옵션(D·E)은 기본 꺼짐 = 동결 모델 바이트 동일(파라미터·출력, mix/CI, D 6/28, H 96/720 확인). D 는 +D, E 는 +8D+4 파라미터.

## 절차
- 공통: L 96, 시드 2025, 산업 6 데이터 × 4 H, batch 32 · 50 epoch · patience 10, 결과 role `redesign` (`run.py --stage redesign`).
  A 의 lr 1e-3 값 = 이미 있는 main 의 시드 2025 행(같은 설정) 재사용.
- **1단계**: B·C·D·E 를 lr 1e-3(동결 값)으로 (96 런). A~E 5개 중 1등을 아래 규칙으로 고른다.
- **2단계**: 1단계 1등에 lr ×0.3(3e-4)·×3(3e-3) 두 개 추가 (48 런). 1등의 1e-3 포함 3개 중 같은 규칙으로 1등.
- **판정 규칙 (베이스라인 `select_verdict.py` 와 같음)**: 데이터마다 후보들을 검증 손실(4 H 평균)로 순위 매기고, 6 데이터 평균 순위
  1등. 동점이면 파라미터가 적은 쪽, 그다음 A 에 가까운 쪽(A > B > D > E > C). 건강 검사도 같음(값이 유한하지 않거나, best epoch
  ≤ 2 인 칸이 절반 초과면 제외). 테스트 오차는 1·2단계에서 읽지 않는다.
- **3단계**: 고른 설정을 3 시드(2025–2027)로 main 처럼 돌려 테스트 1회. 고른 것이 A 면 지금 결과 그대로(재설계 없음).

## 보고 (결과와 상관없이)
- 후보 7개(A~E + lr 2개)와 각 검증 순위, 고른 설정의 테스트 결과를 원고(방법 또는 부록)에 그대로 쓴다.
- 고른 것이 A 가 아니면: 칩 판정(`deployment/board/chip_verdict.py`)과 C 포트를 그 설정으로 다시 하고, 보드 지연을 다시 잰다.
- 지표·규칙·후보를 결과를 보고 바꾸지 않는다. 다른 후보를 추가로 시도하면 그것도 시도 수에 넣어 공개한다.
- LTSF(FEATHer-CI)에 같은 변경을 적용할지는 3단계 뒤 따로 정한다(이 문서 범위 밖).
