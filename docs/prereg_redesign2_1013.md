# 사전 등록: FEATHer 재설계 2라운드 — 데이터 관찰에서 나온 구조 + 크기 맞춘 비교 (2026-10-13, 실행 전에 작성·커밋)

## 왜
10-13 에 메인 비교를 **크기를 맞춘 비교**(1K판 · 칩 최대판)로 바꿨다(`docs/EXPERIMENT_PROTOCOL.md` §10). 베이스라인은 고른
저자 설정에서 크기 다이얼 하나만 바꾸고 lr 을 {×0.1, ×1, ×10} 중 검증으로 다시 고른다. FEATHer 도 **같은 규칙**으로 다시 만든다.
구조는 학습 구간만 쓴 데이터 관찰에서 정한다(`tools/paper/observe_structure.py` → `results/analysis/observation_20261013.csv`).

### 관찰 (학습 구간 앞 70 %, 검증·테스트 미사용)
1. **센서들이 함께 움직인다**: 같은 시점의 다른 센서로 한 센서를 설명하는 R² = 0.82~0.89 (Steel · WindSCADA · BlastFurnace ·
   MetroPT3), 0.49~0.53 (N2O · EWELD). 공통 성분 2~4개로 분산 90 % (Steel · WindSCADA · MetroPT3), 8~9개 (BlastFurnace · N2O · EWELD).
   → **저랭크 섞기**를 유지하고, 섞기 폭 R 은 4 와 8 을 후보로 둔다.
2. **SPK 헤드가 쓰는 주기(≤ 48, L·H 를 나눠야 함) 성분은 분산의 0~5 %** 다(실제 주기는 하루: 96 · 144 · 288 등).
   → 헤드를 주기에 묶지 않는다: **구간 길이 s 를 주기와 분리한 구간 헤드**(s = P 이면 지금 SPK 헤드와 같은 계산).
3. **변동의 62~82 % 가 입력 창(96 스텝)보다 느리다**(Steel 39 %). → 짧은 규모 필터(밴드 3개 + 게이트)는 빼고,
   수준 처리(정규화)를 후보로 둔다.

### 이미 본 결과 (정직 공개)
- FEATHer 의 테스트 결과는 9월 개발부터 여러 번 봤다(구조·섞기 폭·채널 방식 결정 일부 포함).
- **ablation 의 선형 헤드(밀집 L × H) 테스트 결과를 이미 봤다**: 동결 FEATHer-mix 대비 H 별 −5.5 / −4.4 / −2.9 / −1.9 %,
  칩 풀 평균 MSE 0.674(1등)이지만 H ≥ 336 은 칩 밖. 이 결과가 "헤드 용량" 방향을 제안했다.
- 재설계 1라운드(`docs/prereg_redesign_1012.md`) 1단계 검증 결과: 정규화 끄기(`rd:norevin`) 1등. 2단계(lr)는 **실행하지 않고**
  이 문서로 대체한다(크기 맞춘 비교로 규칙이 바뀌었기 때문). 1라운드 후보 5개 + 이 문서 후보는 모두 시도 수로 공개한다.

## 구조 (모든 후보 공통)
```
입력 (L 96 × D) → 수준 처리 → 저랭크 섞기 x + W_up·GELU(W_down·x)  (D → R → D, 시점마다)
               → 공유 다듬기 합성곱 (폭 2⌊P/2⌋ + 1, 모든 채널이 하나를 공유, P = 프로토콜 주기 규칙)
               → 구간 헤드: 창을 길이 s 구간 L/s 개로 나누고, 구간 안 위치마다 같은 선형 사상 (L/s) → (H/s) (위치·채널 공유)
               → 수준 복원
```
- 밴드 3개 · FFT 게이트 · 스펙트럼 분리 손실은 **없음**(손실 = 관측값 MSE 만).
- 다듬기 합성곱은 지금 FEATHer-mix 의 채널별(BlastFurnace 1,372개) 대신 공유(SparseTSF 와 같음).
- **추론 시 등가 구조를 밝힌다**: 수준 처리 · 섞기 MLP(유일한 비선형) 외에는 전부 선형이라, 다듬기 + 구간 헤드는 채널 공유
  선형 사상 하나(구간 안 위치별 블록 구조)로 합쳐진다. s = 1 이면 밀집 선형 헤드, s = P 이면 SPK 헤드.
- 출처: 구간 단위 헤드 = SparseTSF [Lin2024a] 의 주기 헤드 + CMoS [ICML'25] 의 구간 길이 분리. 우리 기여 = 칩 예산 안의 저랭크 섞기와
  관찰에서 나온 설계 · 크기 맞춘 배포 비교.

## 후보 (6개)

|---|---|---|
| `v2:revin-R4` / `v2:revin-R8` | RevIN (창 평균 · 표준편차) | 4 / 8 |

## 크기 (베이스라인과 같은 규칙)
- **다이얼 = 구간 길이 s** ∈ {1, 2, 3, 4, 6, 8, 12, 16, 24, 48} (L 96 과 모든 H 를 나누는 값). 데이터마다 값 하나, 4 H 공통.
- **1K판**: 후보 · 데이터마다, 칩에 저장하는 숫자가 4 H 모두 ≤ 1,000 인 가장 작은 s(= 가장 큰 모델).
- **칩 최대판**: 후보 · 데이터마다, 실제 펌웨어 빌드로 4 H 모두 flash 128 KB · SRAM 20 KB 안인 가장 작은 s.
- C 포트를 새로 만든다(공통 C 규칙: 계산 그대로, 메모리만 정리, 출력은 구간 단위로 바로 내보냄, 재계산 없음). 골든 테스트로
  PyTorch 와 일치 확인 후 빌드.

## 선택 절차 (검증만, 테스트 오차는 읽지 않음)
- 공통: L 96, 시드 2025, 산업 6 데이터 × 4 H, batch 32 · 50 epoch · patience 10, 학습 조건은 베이스라인과 같음.
- 판 (1K · 최대) 마다 따로:
  1. **lr**: 후보마다 lr ∈ {1e-4, 1e-3, 1e-2} (기준 1e-3 의 ×0.1 · ×1 · ×10). 데이터마다 검증 손실(4 H 평균) 순위 → 6 데이터 평균
     순위 1등 lr. (6 후보 × 3 lr × 24 칸 = 432 런 / 판)
  2. **후보**: 각 후보의 고른 lr 결과로 같은 순위 규칙 → 1등 후보.
  - 건강 검사 · 동점 규칙: 베이스라인(`select_verdict.py`)과 같음. 동점이면 작은 모델, 그다음 R4, 그다음 revin > level > none.
- **교차 점검 (보고만, 선택을 바꾸지 않음)**: 데이터 하나를 빼고 나머지 5개로 같은 규칙을 6번 돌려, 빠진 데이터에서 고른 것이
  6개로 고른 것과 같은지(일치 수)를 보고한다. 3단계 뒤 그 빠진 데이터의 테스트 값도 함께 보고한다.

## 테스트 (판마다 고른 하나만)
- 3 시드(2025~2027) × 24 칸, 검증 최적 epoch 에서 테스트 1회. 비교는 베이스라인과 같은 규칙: 모든 모델이 칩에 들어가는 칸끼리의
  순위(검정 = 데이터 단위 단측 Wilcoxon), 칸별 풀 순위(겨룬 칸 수 표시), 모델 간 1:1 승률.
- 보드: 고른 구조의 C 포트로 가장 빠듯한 칸 실측(출력 일치 · 스택 · 지연).

## 보고 (결과와 상관없이)
- 후보 6개 × lr 3개 × 판 2개의 검증 순위, 고른 설정, 교차 점검 일치 수, 테스트 결과를 원고(방법 또는 부록)에 그대로 쓴다.
- 고른 모델이 베이스라인보다 나빠도 그대로 보고한다. 결과를 본 뒤 후보 · 규칙 · 지표를 바꾸지 않는다. 추가로 시도하는 것이 있으면
  새 사전 등록 문서를 먼저 쓰고 시도 수에 넣는다.
- LTSF(FEATHer-CI)에 같은 구조를 쓸지는 이 문서 범위 밖(따로 정함).

  꺼짐 = 동결 모델 바이트 동일(파라미터 · 출력) 확인. 밴드 없음 = 기존 `--front none`, 수준 처리 = 기존 `--no_revin` ·
